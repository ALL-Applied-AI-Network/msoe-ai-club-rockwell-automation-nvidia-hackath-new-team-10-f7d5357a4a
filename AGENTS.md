# VIAL GUARD AI — Agent Operating Instructions

## Mission

Build a safety-first visual inspection agent for a robotic vial production station using synthetic training data generated by a digital twin.

The system inspects two fixtures, G (good) and S (scrap), each containing 30 numbered positions.

## Primary Objective

Minimize defective vials escaping inspection. Missed defects are more costly than false alarms.

## Architecture Principles

1. Use fixed fixture coordinates and target-aware crops.
2. Train inspection models using synthetic digital twin images.
3. Preserve the dataset's exact five-class label taxonomy.
4. Separate visual inference from deterministic manufacturing rules.
5. Track placement events, expected occupancy, and order completion.
6. Treat uncertain inspections conservatively.
7. Preserve an untouched test set for final evaluation.
8. Never claim a defect has been detected without supporting evidence.

## Agent Workflow

- Read the relevant stage SKILL.md before starting.
- Verify dependencies and required inputs.
- Implement only the assigned stage's scope.
- Write automated tests for each acceptance criterion.
- Record assumptions, failures, and unresolved blockers.
- Update the stage status after successful validation.
- Do not bypass quality gates.

## Required Inspection Outputs

Every inspected target position must have:

- Source image identifier
- Fixture identifier (G or S)
- Numbered position identifier
- Expected occupancy
- Predicted visual class
- Model score and applicable threshold
- Inspection decision
- Explanation or reason code
- Timestamp or placement event identifier

## Safety Rules

- Never automatically pass an unresolved suspected defect.
- Never interpret a trailing unfilled position as a missed placement without supporting sequence information.
- Never infer that a defective vial is acceptable in fixture G.
- Never allow a language model to override deterministic safety rules.
- Never use final test-set results to tune model parameters.

## Definition of Done

A stage is complete only when:

- Required outputs exist.
- Acceptance tests pass.
- Evaluation artifacts are saved.
- Known limitations are documented.
- Downstream dependencies are satisfied.
